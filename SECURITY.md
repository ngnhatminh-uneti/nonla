# Security Policy

## Supported versions

Security fixes are applied to the current production branch and the active development branch.

## Reporting a vulnerability

Do not open a public issue for a security vulnerability.

Please report the issue privately to the repository owner through GitHub's private vulnerability reporting or another private channel available to the maintainer. Include reproduction steps, affected route/file, impact, and any relevant logs without sharing secrets.

Never include passwords, API keys, database credentials, `CRON_SECRET`, session tokens, or other credentials in a report.
